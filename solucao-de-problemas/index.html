Solução de Problemas & Diagnóstico de Rede

Encontre soluções objetivas para as causas mais comuns de erro de conexão, bloqueio por roteadores Wi-Fi e permissões de sistema no Windows e Linux.

Como Rodar o Teste Granular (--test-connection)

Em vez de tentar se conectar no escuro, execute o comando de diagnóstico do Nexa indicando o IP da máquina remota. Ele testará cada camada isoladamente:

nexa-daemon --test-connection 192.168.1.20:25800

Causa Mais Frequente: O roteador Wi-Fi está com o recurso de AP Isolation (Isolamento de Clientes) ativado. Comum em redes de visitantes ou roteadores com isolamento entre bandas de 2.4 GHz e 5.0 GHz.

Como Resolver:

  1. Verifique se o IP digitado está correto executando nexa-daemon --interfaces no computador de destino.
  2. Acesse o painel de administração web do seu roteador Wi-Fi (geralmente 192.168.1.1 ou 192.168.0.1).
  3. Procure por opções como Client Isolation, AP Isolation ou Isolamento de Estação e desmarque essa opção.

Causa: O computador de destino responde na rede, mas nada está escutando na porta TCP 25800 ou o firewall bloqueou o tráfego de entrada.

Como Resolver:

  1. Certifique-se de que o Nexa está em execução na máquina de destino com --server ou --client.
  2. No Windows, adicione a regra de firewall com netsh advfirewall firewall add rule name="Nexa KVM Share" dir=in action=allow protocol=TCP localport=25800.
  3. No Linux, libere o firewall UFW com sudo ufw allow 25800/tcp.

Causa: O usuário atual no Linux não possui permissão de escrita no driver de emulação /dev/uinput.

Como Resolver:

Execute no terminal do Linux:

sudo modprobe uinput && sudo chmod 666 /dev/uinput && sudo usermod -aG input $USER

Encerre a sessão gráfica e entre novamente para aplicar o novo grupo do usuário.

Atalho de Emergência KVM: Pressione Esc ou Scroll Lock no teclado físico conectado ao computador principal (Host).

O Nexa suspenderá a captura remota instantaneamente e moverá o cursor para o centro da sua tela local.
