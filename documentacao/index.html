Documentação Oficial & Referência de Comandos

Tabela de flags aceitas pelo binário nexa-daemon, schema do arquivo declarativo nexa.toml e sumário dos 8 crates do workspace Cargo.

1. Parâmetros de Linha de Comando (CLI)

Parâmetro Descrição e Efeito no Sistema
-h, --help Exibe a mensagem de ajuda com todos os comandos disponíveis.
-v, --version Exibe a versão compilada (exemplo: nexa-daemon v0.1.0).
-c, --config <ARQUIVO> Especifica o caminho para um arquivo de configuração customizado.
-p, --port <PORTA> Altera a porta TCP de escuta do servidor KVM (Padrão: 25800).
--server Executa em modo Servidor (Host com mouse e teclado físicos).
--client <IP[:PORTA]> Executa em modo Cliente (Guest que recebe o controle do cursor à distância).
--test-connection <IP[:PORTA]> Executa a rotina diagnóstica em 5 etapas contra um nó remoto na rede.
--interfaces Lista todas as interfaces de rede locais (Ethernet / Wi-Fi) e endereços IPv4.
--no-discovery Desativa a descoberta automática de nós locais via broadcast UDP (porta 25801).
--gui Inicia o servidor web interno e abre o navegador na GUI (comportamento padrão).
--no-gui, --headless Executa silenciosamente em linha de comando sem instanciar o servidor da interface gráfica.
--gui-port <PORTA> Altera a porta da interface gráfica web (Padrão: 25802).
--autostart-enable Gera as instruções para agendamento de tarefa elevado no logon do sistema.

2. Arquivo de Configuração Declarativo (nexa.toml)

O arquivo nexa.toml permite salvar configurações de topologia, nós confiáveis e portas:

nexa.toml 
device_name = "Meu-PC-Windows"
listen_port = 25800
edge_delay_ms = 0
auto_connect = true
log_level = "info"

[[peers]]
name = "Linux-Laptop"
ip_or_host = "192.168.1.20"
port = 25800
public_key_hex = "7f3a0981884c7d659a2feaa0c55ad015a3bf4f1b2b0b822cd15d6c15b0f00a08"
is_trusted = true
alias = "Laptop elementary OS"
manual_ip = "192.168.1.20"
manual_port = 25800

3. Módulos Internos do Workspace Cargo

O Nexa é dividido em 8 bibliotecas especializadas para manutenção e compilação limpas:

nexa-protocol

Framing binário de 16 bytes com Magic 0x4E455841, serialização e checksum CRC32.

nexa-crypto

Canal seguro ChaCha20-Poly1305, troca X25519, identidade Ed25519 e derivação do PIN SAS.

nexa-core

FSM de sessão, conversão de topologia 2D, coalescedor de mouse de 3ms e clipboard Anti-Echo.

nexa-net

Servidor/Cliente TCP com Tokio, broadcast UDP local e diagnóstico granular em 5 etapas.

nexa-platform

Low-Level Hooks Win32, injeção SendInput e driver de kernel Linux /dev/uinput.

nexa-ui

Servidor HTTP embutido em 127.0.0.1:25802 e interface gráfica web reativa.
