1. Visão Geral do Nexa

O Nexa é um sistema multiplataforma escrito em Rust 2021 que permite utilizar um único teclado e mouse físicos conectados a um computador primário (Host/Servidor) para controlar um ou mais computadores secundários (Guest/Cliente) posicionados lado a lado, com suporte nativo a sincronização de área de transferência (clipboard).

Diferente de soluções legadas em C++ (Synergy 1.x, Barrier, Deskflow), o Nexa foi projetado com:

  • Memory-safety garantida pelo Rust: Ausência total de vazamentos de memória, corrupção de buffer e travamentos silenciosos.
  • Criptografia moderna de ponta a ponta: ChaCha20-Poly1305 por padrão em todos os pacotes, com pareamento visual anti-MITM via código SAS numérico.
  • Compatibilidade com Wayland moderno: Suporte planejado para o portal InputCapture e injeção eficiente via driver de kernel /dev/uinput.
  • Suporte a mouses gamers de alto polling rate: Coalescência em janelas de 3ms reduzindo 75% da banda sem perda de fluidez.
💡
Aviso de Desenvolvimento: O Nexa está em desenvolvimento ativo (versão 0.1.0). As funcionalidades documentadas refletem exatamente o código-fonte atual verificado por testes de integração.

2. Arquitetura dos 8 Crates

O repositório do Nexa é estruturado como um workspace Cargo modular composto por 8 crates independentes:

Crate Responsabilidade Técnica Status
nexa-protocol Framing binário de 16 bytes com Magic (0x4E455841), versionamento, codec e validação de integridade por CRC32. Pronto
nexa-crypto Identidade Ed25519, troca efêmera ECDH X25519, derivação HKDF-SHA256, canal ChaCha20-Poly1305 e cálculo do PIN SAS de 6 dígitos. Pronto
nexa-core Máquina de estados finitos (FSM), SessionEngine, conversão geométrica proporcional 2D, Coalescedor de mouse e motor Anti-Echo de clipboard. Pronto
nexa-net Servidor e cliente TCP assíncronos (Tokio), anúncios LAN via UDP broadcast periódica (porta 25801) e ferramenta de diagnóstico de 5 passos. Pronto
nexa-platform Win32 Low-Level Hooks (WH_MOUSE_LL, WH_KEYBOARD_LL), injeção SendInput, DPI awareness e driver Linux /dev/uinput. Pronto (Win/Lin Guest)
nexa-ui Servidor web embutido em 127.0.0.1:25802, canvas de monitores, alternador de telas e painel de diagnóstico em tempo real. Pronto
nexa-daemon Binário executável de orquestração com suporte a modos headless, serviço de background, gerador de autostart e CLI completa. Pronto
nexa-common Tipos fundamentais de erro (NexaError), constantes globais e subsistema de logging com mascaramento automático de chaves. Pronto

3. Manual de Instalação — Windows 11 / 10 (x64)

O Nexa opera no Windows em modo nativo, compatível com monitores de alto DPI e escalonamento fracionário (125%, 150%, 200%).

Requisitos do Windows

  • Windows 11 (todas as edições) ou Windows 10 (64-bit, versão 1809 ou superior).
  • Privilégio de Administrador local para criação da regra de firewall e agendador de tarefas elevado.
  • Adaptador Wi-Fi ou cabo Ethernet na mesma sub-rede local.

Passo 1: Instalação e Extração

Baixe o pacote compactado e descompacte em um local permanente (ex: C:\Nexa\):

https://github.com/rafaelmaciels/Nexa/releases/latest/download/nexa-windows-x64.zip

Passo 2: Liberação de Firewall no Windows

Abra o PowerShell como Administrador e execute o comando abaixo para permitir a entrada de conexões KVM:

PowerShell (Administrador) 
netsh advfirewall firewall add rule name="Nexa KVM Share" dir=in action=allow protocol=TCP localport=25800 profile=any

Passo 3: Execução com Suporte a UAC Elevado

Para que o cursor do mouse e o teclado continuem funcionando mesmo quando uma janela administrativa (com permissões UAC) estiver em primeiro plano, o Nexa deve iniciar via Agendador de Tarefas com privilégios elevados. O próprio daemon gera os comandos de configuração:

.\nexa-daemon.exe --autostart-enable

4. Manual de Instalação — Linux (elementary OS 8.1 / Ubuntu / Debian)

No Linux, o Nexa utiliza o driver de emulação de kernel /dev/uinput, permitindo injetar movimentos de mouse e toques de teclado sem necessidade de rodar o programa como superusuário (root).

Instalação via Pacote Oficial Debian (.deb)

Terminal Bash 
wget https://github.com/rafaelmaciels/Nexa/releases/latest/download/nexa_0.1.0_amd64.deb
sudo dpkg -i nexa_0.1.0_amd64.deb
sudo apt-get install -f

Script Automatizado de Permissões (/dev/uinput)

Execute a linha única oficial para carregar o módulo do kernel e adicionar seu usuário ao grupo input:

sudo modprobe uinput && sudo chmod 666 /dev/uinput && sudo usermod -aG input $USER

Regra Definitiva do Udev (/etc/udev/rules.d/99-nexa-uinput.rules)

Para que a permissão persista após reinicializações do sistema sem precisar rodar comandos adicionais:

Configuração Persistente Udev 
echo 'KERNEL=="uinput", SUBSYSTEM=="misc", TAG+="uaccess", OPTIONS+="static_node=uinput", MODE="0666"' | sudo tee /etc/udev/rules.d/99-nexa-uinput.rules
sudo udevadm control --reload-rules
sudo udevadm trigger

Serviço de Inicialização Automática (systemd --user)

O Nexa roda perfeitamente integrado à sua sessão gráfica de usuário:

systemctl --user enable --now nexa.service

5. Referência de Linha de Comando (`nexa-daemon`)

O binário nexa-daemon aceita as seguintes opções:

Opção Descrição Técnica
-h, --help Exibe a mensagem de ajuda e resumo de sintaxe.
-v, --version Exibe a versão compilada do software (ex: 0.1.0).
-c, --config <ARQUIVO> Especifica um caminho customizado para o arquivo de configuração TOML.
-p, --port <PORTA> Define a porta TCP de escuta do servidor (Padrão: 25800).
--server Executa em modo Servidor (Host que possui o mouse/teclado físico).
--client <IP[:PORTA]> Executa em modo Cliente (Guest que recebe as coordenadas e eventos de entrada).
--test-connection <IP[:PORTA]> Executa o teste de diagnóstico de rede em 5 etapas contra um nó remoto.
--interfaces Lista todas as interfaces de rede ativas na máquina e seus endereços IPv4.
--no-discovery Desativa o serviço de anúncio automático via broadcast UDP na porta 25801.
--gui Inicia o servidor web interno e abre a interface gráfica no navegador padrão.
--no-gui, --headless Executa em modo silencioso/terminal sem instanciar o servidor web da UI.
--gui-port <PORTA> Altera a porta local da interface gráfica web (Padrão: 25802).
--autostart-enable Gera e exibe as instruções e scripts de inicialização automática no SO.
--autostart-disable Gera os comandos para remoção da inicialização automática no sistema.

6. Arquivo de Configuração Declarativo (`nexa.toml`)

O Nexa salva sua configuração em formato declarativo TOML. Quando não especificado via -c, ele procura por nexa.toml na pasta de execução do binário ou no diretório de configuração do usuário:

nexa.toml (Exemplo Completo) 
# Identificação da máquina local
device_name = "Meu-PC-Windows"
listen_port = 25800
edge_delay_ms = 0
auto_connect = true
log_level = "info"

# Lista de computadores emparelhados e confiáveis
[[peers]]
name = "Linux-Laptop"
ip_or_host = "192.168.1.20"
port = 25800
public_key_hex = "7f3a0981884c7d659a2feaa0c55ad015a3bf4f1b2b0b822cd15d6c15b0f00a08"
is_trusted = true
alias = "Laptop elementary OS"
manual_ip = "192.168.1.20"
manual_port = 25800

7. Segurança Criptográfica & SAS PIN

Em um software de compartilhamento de teclado, a segurança é crítica: se os pacotes fossem transmitidos em texto claro, qualquer dispositivo na rede Wi-Fi poderia capturar senhas digitadas, números de cartão e credenciais.

Garantias Criptográficas do Nexa:

  • Identidade por Chave Ed25519: Cada máquina gera uma identidade criptográfica única de 32 bytes persistida localmente.
  • Troca Efêmera de Chaves (X25519): Para cada sessão TCP, novos pares de chaves efêmeras são criados, garantindo Perfect Forward Secrecy (PFS).
  • Cifra Autenticada ChaCha20-Poly1305: Impossibilita adulteração de pacotes em trânsito; qualquer bit modificado causa rejeição instantânea da conexão.
  • Proteção Anti-Replay: Contadores de nonce sequenciais estritos e prefixos diferenciados por direção (SRV\x01 vs CLI\x01).
  • Código Numérico SAS PIN de 6 Dígitos: Derivado via HKDF-SHA256, exibido em ambas as telas na primeira conexão para validação visual humana, eliminando qualquer ataque de Homem-no-Meio (MITM).

8. Solução de Problemas Comuns (Troubleshooting)

Causa: Roteador Wi-Fi com o recurso AP Isolation ou Client Isolation ativado (bloqueia computadores na mesma rede de conversarem entre si), ou máquina de destino em outra sub-rede.
Solução: Acesse as configurações do seu roteador Wi-Fi e desative o isolamento de clientes (Client Isolation). Certifique-se de que o IP não foi alterado pelo DHCP executando nexa-daemon --interfaces.
Causa: O nexa-daemon não está em execução na máquina de destino ou o firewall (Windows Firewall / UFW) bloqueou a porta 25800.
Solução: Inicie o Nexa na outra máquina com --server ou --client e adicione a regra de liberação de porta descrita nas seções 3 e 4.
Causa: Falta de permissão de escrita no dispositivo /dev/uinput.
Solução: Execute sudo usermod -aG input $USER && sudo chmod 666 /dev/uinput e encerre/reinicie a sessão gráfica.
Solução de Emergência KVM: Pressione a tecla Esc ou Scroll Lock no teclado físico. O Nexa soltará a captura imediatamente e reposicionará o cursor no centro do monitor principal local.
